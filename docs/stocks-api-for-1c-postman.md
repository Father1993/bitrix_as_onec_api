# API остатков `as.onec_api` для 1С-программиста

Краткий рабочий документ для быстрой проверки API остатков в Postman без погружения в код модуля.

## Что есть в модуле по остаткам

Для остатков используются два основных эндпоинта:

- `GET /v1/stocks` — прочитать остаток товара по `xml_id`
- `POST /v1/stocks/import` — передать остатки из 1С в Битрикс

Дополнительно `POST /v1/stocks` работает так же, как `POST /v1/stocks/import`.

Основная точка входа:

- `{{base_url}} = https://ваш-сайт/local/tools/as_onec_api.php`

Во всех запросах используется параметр:

- `path=/v1/stocks`
- или `path=/v1/stocks/import`

## Авторизация

Предпочтительный вариант для Postman:

- заголовок `X-Stock-Import-Key: {{access_key}}`

Допустимые варианты авторизации:

- заголовок `X-Stock-Import-Key`
- поле `access_key` в корне JSON-объекта
- `login` и `password` в корне JSON-объекта для POST

Для GET лучше использовать заголовок или `access_key` в query, но не `login/password`.

## Что важно понять до тестирования

### 1. В Битрикс есть два режима учёта остатков

Модуль сам работает по-разному в зависимости от настройки Битрикс:

- если складской учёт выключен, остаток хранится как одно число товара
- если складской учёт включён, остатки хранятся по складам

Это влияет и на чтение, и на импорт.

### 2. Один и тот же HTTP 200 не означает полный успех

Для импорта важно смотреть не только на HTTP-код, но и на поля ответа:

- `updated`
- `failed`
- `errors`
- `errors_truncated`

Если в ответе `failed > 0`, значит часть строк не была применена.

### 3. Неоднозначный `XML_ID` товара считается ошибкой

Если в каталоге найдено несколько элементов с одним и тем же `XML_ID`, модуль не обновляет такую строку и возвращает ошибку по позиции.

Это сделано специально, чтобы не обновить не тот товар.

## Как читать остатки

### Запрос в Postman

- Method: `GET`
- URL: `{{base_url}}?path=/v1/stocks&xml_id=ВАШ_XML_ID`
- Headers:
  - `X-Stock-Import-Key: {{access_key}}`

### Что смотреть в ответе

#### Если складской учёт выключен

В ответе будет:

- `inventory_management: false`
- `quantity`

Это итоговый остаток товара.

#### Если складской учёт включён

В ответе будет:

- `inventory_management: true`
- `stores`
- `quantity_total`
- `catalog_quantity`

Смысл полей:

- `stores` — остатки по конкретным складам
- `quantity_total` — сумма всех `stores[].amount`
- `catalog_quantity` — агрегированный остаток товара в каталоге Битрикс

### Как правильно трактовать `quantity_total` и `catalog_quantity`

Для интеграции это критично:

- для проверки складов ориентируйтесь на `stores` и `quantity_total`
- для проверки того, что видит каталог и витрина, ориентируйтесь на `catalog_quantity`

Возможна ситуация:

- `quantity_total = 0`
- `catalog_quantity > 0`

Это не обязательно ошибка интеграции. Такое бывает, пока по товару ещё нет строк складов, а агрегированный остаток в каталоге уже есть.

## Как передавать остатки из 1С

### Минимальный рабочий запрос в Postman

- Method: `POST`
- URL: `{{base_url}}?path=/v1/stocks/import`
- Headers:
  - `Content-Type: application/json`
  - `X-Stock-Import-Key: {{access_key}}`
- Body: `raw` -> `JSON`

Пример тела для одной позиции:

```json
{
  "items": [
    {
      "product_xml_id": "ВАШ_XML_ID_ТОВАРА",
      "amount": 5
    }
  ]
}
```

Если складской учёт включён, обычно нужно передавать ещё и склад:

```json
{
  "items": [
    {
      "product_xml_id": "ВАШ_XML_ID_ТОВАРА",
      "amount": 5,
      "store_id": 1
    }
  ]
}
```

## Какие поля понимает импорт остатков

### Идентификация товара

Можно передавать:

- `product_xml_id`
- `xml_id`
- `XML_ID`
- `product_id`

Приоритет практического использования:

- для внешней интеграции лучше использовать `product_xml_id`
- `product_id` подходит, если 1С уже знает внутренний ID Битрикс

### Количество

Можно передавать:

- `amount`
- `quantity`

Правила:

- значение должно быть числом
- отрицательные значения запрещены
- `0` допустим и означает остаток ноль

### Идентификация склада

При включённом складском учёте можно передавать:

- `store_id`
- `store_xml_id`
- `store_code`

Если складской учёт выключен, склад не нужен.

## Как модуль определяет склад

Если передан `store_id`, используется он.

Если `store_id` не передан, модуль пытается определить склад по:

- `store_xml_id`
- `store_code`

Дополнительно модуль умеет сопоставлять склад через значение свойства `MESTO_KHRANENIYA`, если в проекте этот механизм используется для обмена с CommerceML.

Если склад не передан и не найден:

- модуль пробует взять `default_store_id` из настроек модуля

Если и после этого склад не определён:

- строка получает ошибку

## Основные сценарии тестирования в Postman

### 1. Проверка чтения остатка по товару

Проверьте:

- находится ли товар по `xml_id`
- какой режим возвращает API: со складами или без
- совпадает ли результат с ожиданием в админке

### 2. Импорт одной строки без склада

Подходит только если складской учёт выключен, либо в модуле настроен `default_store_id`.

Тело:

```json
{
  "items": [
    {
      "product_xml_id": "ВАШ_XML_ID_ТОВАРА",
      "amount": 3
    }
  ]
}
```

Ожидание:

- `updated = 1`
- `failed = 0`

### 3. Импорт одной строки на конкретный склад

Тело:

```json
{
  "items": [
    {
      "product_xml_id": "ВАШ_XML_ID_ТОВАРА",
      "amount": 7,
      "store_id": 1
    }
  ]
}
```

После этого проверьте `GET /v1/stocks` и убедитесь, что:

- нужный склад появился в `stores`
- у него обновился `amount`
- изменился `quantity_total`

### 4. Импорт по `store_xml_id`

Тело:

```json
{
  "items": [
    {
      "product_xml_id": "ВАШ_XML_ID_ТОВАРА",
      "amount": 4,
      "store_xml_id": "ВАШ_XML_ID_СКЛАДА"
    }
  ]
}
```

Сценарий полезен, если 1С знает внешний код склада, но не знает внутренний `store_id`.

### 5. Обнуление остатка

Тело:

```json
{
  "items": [
    {
      "product_xml_id": "ВАШ_XML_ID_ТОВАРА",
      "amount": 0,
      "store_id": 1
    }
  ]
}
```

Ожидание:

- строка считается валидной
- остаток становится ноль

### 6. Проверка ошибки по отсутствующему складу

Тело:

```json
{
  "items": [
    {
      "product_xml_id": "ВАШ_XML_ID_ТОВАРА",
      "amount": 5
    }
  ]
}
```

Если складской учёт включён и `default_store_id` не настроен, ожидайте ошибку по строке:

- `failed = 1`
- в `errors[]` будет сообщение, что склад не указан

### 7. Проверка ошибки по битому `XML_ID` товара

Тело:

```json
{
  "items": [
    {
      "product_xml_id": "НЕСУЩЕСТВУЮЩИЙ_XML_ID",
      "amount": 5,
      "store_id": 1
    }
  ]
}
```

Ожидание:

- `failed = 1`
- в `errors[]` будет сообщение, что товар не найден

## Как читать ответ импорта

Типичный успешный ответ:

- `ok: true`
- `total` — сколько строк пришло
- `updated` — сколько строк реально применилось
- `failed` — сколько строк не применилось
- `errors[]` — список ошибок по строкам

Если ошибок очень много, список может быть обрезан:

- `errors_truncated: true`

Это значит, что ошибок больше, чем вернулось в теле ответа, и нужно смотреть логи или разбирать пакет меньшими частями.

## Типовые причины ошибок

На что смотреть в первую очередь:

- не передан `xml_id` товара и не передан `product_id`
- `amount` не число
- `amount` отрицательный
- складской учёт включён, но склад не передан и не определён
- склад неактивен
- товар не найден
- найдено несколько товаров с одинаковым `XML_ID`
- неверный ключ доступа
- превышен лимит размера тела или числа строк

## Практический порядок быстрой проверки

Для быстрого старта в новом проекте удобно идти так:

1. Проверить `GET /v1/stocks` по одному известному товару.
2. Понять, включён ли складской учёт по полю `inventory_management`.
3. Отправить один `POST /v1/stocks/import` на один товар.
4. Сразу повторно проверить `GET /v1/stocks`.
5. Только после этого отправлять пакет из нескольких позиций.

## Что нужно помнить при интеграции с 1С

- если Битрикс работает со складами, 1С должна передавать склад или должен быть настроен `default_store_id`
- `200 OK` не означает, что все строки применились
- для чтения склада ориентируйтесь на `stores` и `quantity_total`
- для витрины и карточки товара ориентируйтесь на `catalog_quantity`
- одинаковый `XML_ID` у нескольких товаров блокирует безопасный импорт по этой позиции
